Read the relevant file first when a task spans areas or starts from the repo root. Production grade, verified,
no guesswork.

## Gotchas
- Dev Postgres: `POSTGRES_MODE` in `.env` is `docker` (compose, host port from `POSTGRES_PORT`; `make db-up`) or `local` (installed server at `DATABASE_URL`; `psql` must be on PATH, e.g. `/Library/PostgreSQL/18/bin`). Tests use `internal/dbtest.New(t)`.
- Android build: `ANDROID_HOME=~/Library/Android/sdk gradle :shared:testAndroidHostTest :androidApp:assembleDebug` (system gradle; wrapper download timed out).
- Codegen: `make generate` (sqlc + oapi-codegen).
- Dev auth `Bearer dev:<name>` only when `ENV=dev`; prod uses Firebase (`FIREBASE_PROJECT_ID`).
- Environments: local `dev` plus hosted `staging` and `prod`, each a separate GCP/Firebase project + Neon DB + Cloud Run service; steps in `deploy/README.md`. Make targets take `DEPLOY_ENV` (default `staging`; prod only when explicitly asked): `migrate-remote` (`REMOTE_DATABASE_URL_<ENV>` in `curator/.env`), `curator-sync`, `deploy-api` (`deploy/<env>.env`), `android-apk`/`android-bundle`. Never run deploys, migrate-remote or curator-sync yourself.
- Android UI rule: content never scrolls under the status bar or the navigation bar (buttons or gesture handle). Scrolling containers stop at the bars: `Modifier.tabContentBounds(shellPadding)` for tab screens, `windowInsetsPadding(WindowInsets.safeDrawing…)` elsewhere. Only backgrounds (`ScreenBackdrop`, bar fills) draw behind the bars.
- Android flavors `staging`/`prod` (tasks like `assembleStagingDebug`); api URL from `changeloom.<env>.apiBaseUrl`, app ids `dev.changeloom.android.staging` (staging, installs beside prod) and `dev.changeloom.android` (prod), Firebase config from `androidApp/src/<env>/google-services.json`, else `androidApp/google-services.json` (each must have a client for its flavor's app id), release signing from `mobile/keystore.properties`.
- The api no longer syncs topics at startup; tests sync `backend/seed/topics.yaml`.
- Curator: config in `curator/.env` (copy `.env.example`; the Makefile includes it). `make curator-db curator-migrate curator-seed`, then `curator-test`/`curator-lint`. The catalog is `curator/seed/catalog/`: `professions.yaml` (professions → root topic slugs; every root must belong to one; `launch: true` ones are offered at onboarding, at least one required) plus `topics/*.yaml` (roots with `children`, 2 levels; slugs `root/child`; every root has `priority` 1 (highest)–5, a child inherits it unless it sets its own; stored in curator table `topic_priority`; `headline: true` on a topic puts its important stories (importance ≥ `TIMELINE_HEADLINE_MIN_IMPORTANCE`) in every user's timeline, tier `headline` between related and explore). `curator seed` validates it. Commands: `migrate [--remote --env]`, `seed`, `requests`, `fetch`, `backfill [--max-calls N]`, `prune [--env]`, `sync [--env]`, `run` (demand pull, fetch, backfill, sync, then prune each hosted DB every `CURATOR_PRUNE_INTERVAL_DAYS`; user topic requests are separate: `make curator-requests DEPLOY_ENV=` runs `requests pull`, `requests group`, `sync`). `clean [--envs staging,prod] [--apply]` (`make curator-clean [ENVS=] [APPLY=1]`) deletes topics/professions no longer in the catalog, plus unsaved stories only in them, from the local DB and those hosted DBs (seed and sync never delete); anything a user follows, muted, picked or requested is kept; report-only without `--apply`. Fetch frequency follows demand: hot (distinct users who opened (read) or saved a story in 7 days ≥ `CURATOR_HOT_MIN_ENGAGED`) every run, warm (followed, serves a user's profession, headline, or fewer engaged users) every `CURATOR_WARM_INTERVAL_HOURS` (or its priority's interval if shorter), cold (under a launched profession with no demand, or stories seen in 7 days but opened/saved by nobody, even if followed) every `CURATOR_PRIORITY_INTERVAL_HOURS` entry for its priority, and other topics with no demand never (backfill skips them too); within a tier higher priority goes first, then engaged users, then viewers (impressions are only a tiebreak), and backfill orders by priority. Shares aren't stored server-side, so they aren't a signal; users who muted a topic (or its root) aren't demand for it. Prune never deletes saved stories; it deletes unsaved ones older than `CURATOR_PRUNE_MAX_AGE_DAYS` (by `published_at`). All keys are in `curator/.env.example`. `curator fetch` makes real `claude -p` calls (subscription usage); tests fake the CLI.
- Curator AI provider: `CURATOR_AI_PROVIDER` claude|openai (OpenAI-compatible API; no tools are given, so the model must search the web itself). Nothing AI-related runs locally (no Ollama/SearXNG). `make curator-fetch`/`curator-backfill`/`curator-full` take `AI=` `MODEL=` `PROMPT=frontier|compact` for one run.
- Curator schema = `backend/migrations` (read from `BACKEND_MIGRATIONS_DIR`, default `../backend/migrations`, so run it from `curator/`) + `curator/migrations` (goose table `curator_goose_db_version`). Rerun `make curator-generate` after backend migrations change.
